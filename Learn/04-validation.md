## Validation in detail

Moved from `HANDOFF.md` (13 Nov 2026), which keeps the commands.

- App: `tools/check.sh` (repository root) is the one command: unit tests (baseline 523), app and device-test APKs, `:app:lintDebug` (0 errors, 23 version-update warnings; uiautomator 2.4.1, Firebase BOM 35.2.0 and google-services 4.6.0 are deliberately not taken: too new when chosen), `verifyModuleGraph`, `verifyUiModels`, every screenshot suite (183 images: phone, 1.5× font and dark), and the security gate at preBuild; it prints a summary and exits 0 only when all pass (log: `Chronova - Android App/build/reports/check.log`). `--devices` adds every module's device tests (112) on the managed emulator `pixel6api35` (Pixel 6, API 35 Google APIs; nothing on the phone); `--devices-only` runs just those. The emulator needs about 8 GB of free disk: on 13 Nov 2026 it couldn't start with 9 GB free; on 14 Nov, with 31 GB free, `--devices-only` passed (110 tests; the 2 Try demo tests added on 15 Nov passed in the account module's own run). The script runs the device tests in their own Gradle call with `--max-workers=1`: with several modules' test apps on the one emulator at once, one was killed mid-run ("Process crashed", none of its tests reported) while Gradle still exited 0. The summary counts every test class and says FAIL when any test failed, whatever Gradle's exit code. The pre-push hook (`tools/git-hooks/pre-push`, on through `core.hooksPath`) runs `tools/check.sh`; `git push --no-verify` skips it. CI: `.github/workflows/android.yml` runs `tools/check.sh` on macOS (the screenshot references are Mac-rendered) and `--devices-only` on Ubuntu with KVM. Since the repository went to GitHub (`nssamonte-git/chronova`, 14 Nov 2026), the macOS job passed on both finished runs, and the Ubuntu device-test job failed in its "Device tests" step on every run. Cause (15 Nov, from the run's report artifact): `:app`'s test process died in `RotationStateTest.theTalkingAssistantFitsALandscapeScreen` ("status -1", then "Expected 11 tests, received 3") a few seconds after the 3D orb's Filament engine started on the runner's SwiftShader OpenGL ES; it didn't reproduce on the Mac's emulator (SwiftShader through ANGLE). Fixed by not starting Filament on software renderers (`OrbEngine.softwareRenderer`), so the orb shows its plain icon there. `tools/check.sh` now prints each failed test's name and first error line, so CI logs name failures directly.
- Build gate: `Chronova - Android App/build-validator/` (canonical mobile build validator, Native Android) runs as `:app:validateThreats` before every `preBuild`; critical/high findings fail the build (never lower `THRESHOLD` or remove the hook). Run alone: `sh build-validator/validate-build.sh`. Accepted findings need a reason (inline `build-validator:ignore` or `.build-validator-ignore`); 3 medium/low warnings are open on purpose (Keystore key without user auth for background sync, no Play Integrity, no tapjacking/FLAG_SECURE). Release builds run R8 on the whole app (AGP 9 `optimization { enable = true }`; the scanner's AND-RE-001 doesn't know that DSL, recorded in `.build-validator-ignore`). Re-run the installer with `--with-cards` after canonical rule changes. Release signing is done by hand (user choice, 2026-11-13): Android Studio → Build → Generate Signed App Bundle or APK → `release` (R8 already shrinks and obfuscates the whole app). The build has no signing config, so a plain `assembleRelease` stays unsigned. Keep the key outside the repository and backed up (losing it means no updates; on Google Play it is the upload key under Play App Signing); `*.jks`, `*.keystore` and `keystore.properties` are git-ignored.
- On the phone, instrumented tests run only through `am instrument` (never `connectedAndroidTest`: it uninstalls the app and its data); the emulator path above avoids the phone entirely. App tests (11: Room, rotation, pinch): build both APKs, then `TEST_CLASSES=noel.chronova.app.rotation.RotationStateTest,noel.chronova.app.rotation.RotationStressTest,noel.chronova.app.timeline.TimelinePinchTest,noel.chronova.app.data.repository.ApplyChangesRoomTest tools/qa/rotation-stress.sh instrumented` (backs up and restores the app's data; it installs `app-debug.apk`, so build that with the server URL first, see "End to end"). Every other module runs as its own test app with the app's data untouched: `./gradlew :<module>:assembleDebugAndroidTest`, `adb install -r -t` the APK from `<module>/build/outputs/apk/androidTest/debug/`, `adb shell am instrument -w <namespace>.test/androidx.test.runner.AndroidJUnitRunner`, then `adb uninstall <namespace>.test`. Baselines (as run on the emulator, 2026-11-14; the app module has 11): `:core:data` 9 (Room repository), `:core:database` 5 (`MigrationTest`, every old schema to current; add a case when the version goes up), `:core:ui` 9, `:core:designsystem` 7 (the theme, with contrast checks for both themes), `:feature:export:data` 3 (the PDF writer), `:feature:chartimport:data` 5 (images turned, scaled and stripped of metadata), and the feature screens (real screen and ViewModel on `:core:testing` fakes, visible text and semantics only): projects 9, timeline 26, notifications 8, account 12, sync 5, chart import 1. `TimeFormat` has JVM tests in `:core:ui`.
- Screenshots (Compose Preview Screenshot Testing through AGP test suites, experimental; engine pinned as `screenshotEngine`): modules applying `chronova.android.screenshots` keep `@PreviewTest @ChronovaScreenshots` previews in `src/screenshotTest/kotlin` and committed references in `src/screenshotTestDefaultDebug/reference`, each at phone size and 1.5x font. Check with `./gradlew testDebugScreenshotTestDefaultTestSuite` (report: `<module>/build/reports/tests/testDebugScreenshotTestDefaultTestSuite/index.html`). After an intended visual change: `./gradlew updateDebugScreenshotTestDefaultTestSuite`, look at the new PNGs, commit them with the change. Previews use fixed data, the UTC zone and a fixed "now" (`*Content` composables take a `now` clock). In zsh, write module task paths as `:${m}:task` (a bare `$m:u` is an uppercase modifier).
- Rotation stress on the phone: `tools/qa/rotation-stress.sh <scenario|all|list|restore> [cycles] [interval]` (`BURST=20 … all 10 1.0` takes ~30 min). It backs up the app data to `files/qa-backup` on the phone and restores it and the rotation setting on exit, waiting up to 2 min if USB drops (it does, often); `restore` recovers a backup an interrupted run left. Phone quirks: ColorOS refuses `settings put system` from adb (rotate with `wm set-user-rotation lock 0|1`, restore with `free`); Android undoes a fixed rotation set while the app holds its orientation; with the screen off ColorOS freezes the instrumentation process (the script wakes it); `mCurrentRotation` is in degrees.
- Server: `cd server && docker compose up -d && composer test && composer lint` — baseline 528 tests (15 Nov 2026; `phpunit.xml` forces `PUSH_SENDER=fake`, so a local `.env` with `fcm` never reaches Firebase); image: `docker compose --profile test run --rm --build test`.
- Infra: `cd server/infra && npx tsc --noEmit && npm test && npx cdk synth -c mailFrom=no-reply@example.com` — baseline 23 tests, synth without warnings.
- End to end on the phone: local server (`php artisan serve --port=8000` + `queue:work`, + `schedule:work` for pushed reminders; real pushes need `PUSH_SENDER=fcm` and `FCM_CREDENTIALS` in `server/.env`, see `docs/push.md`), `adb reverse tcp:8000 tcp:8000` (re-add after any USB reconnect), `chronova.apiUrl=http://localhost:8000` in `Chronova - Android App/local.properties` for the check only (restore it after). That file has no final newline: append with `printf '\nchronova.apiUrl=…\n'`, or the line joins `sdk.dir` and the build silently has no server (the app then says it isn't connected); check `SYNC_API_URL` in `app/build/generated/source/buildConfig/debug/`.
- For UI or gesture changes: `cd "Chronova - Android App" && ./gradlew :app:installDebug` on the physical phone (Android 10, 360 dp wide, authorized over USB), then `adb exec-out screencap -p`. Predict the expected pixel or time values before running the check.
- `sh scripts/engineering-health-summary.sh` gives a combined report.
